# 分拣打票与配送支持

## Context
鼎恒餐饮供应链系统已有完整的采购订单流转（待确认→已确认→已发货→已完成）与商家/供应商/开发者三端鉴权。本次需在不破坏既有流程前提下，补齐线下履约三件套：①供应商打票（80mm 热敏小票 + 一键打全票）②分拣过秤（电子秤接口 + 按实称重算金额 + 分拣标签打印）③配送三件套（商家填门店定位/门头照/收货方式 + 供应商配送单页含高德导航与拍照送达）。

## 状态映射（不改 status enum）
- 待分拣 = status `已确认` + `sorted=false`；全部行过秤后 `sorted=true`
- 待配送 = status `已发货`（deliveryPhotoUrl 空）；送达拍照后 deliveryPhotoUrl/deliveredAt 写入（仍处已发货，商家确认收货→已完成）

## 模型改动
**models/PurchaseOrder.js**
- `purchaseItemSchema` 加：`actualWeight`(Number,default 0)、`weighed`(Boolean,default false)、`actualLineTotal`(Number,default 0)
- `purchaseOrderSchema` 顶层加：`sorted`(Boolean,default false,index)、`sortedAt`(Date)、`deliveryPhotoUrl`(String)、`deliveredAt`(Date)

**models/Setting.js**（沿用 Setting 作 shopId 配置聚合表，与 bannerImage/logoImage 同类）
- `shopLongitude`/`shopLatitude`(Number)、`shopAddress`(String)
- `storeFrontPhoto`(String,必传)、`streetViewPhoto`(String,选传)
- `receiveMethod`(enum: door_container/open_door/self_pickup)
- `expectedReceiveStart`/`expectedReceiveEnd`(String HH:mm，默认 06:00/09:00)

## 路由改动（routes/purchaseOrders.js）
顶部 `require('../models/Setting')`。新增三接口：
1. `GET /:id`（verifyToken）：按 role 校验归属；populate supplier/coupon；ShopAccount 补 shopContact/shopPhone；**读 Setting 补 shopLongitude/shopLatitude/shopAddress/storeFrontPhoto/receiveMethod/expectedReceive* 供配送单页用**
2. `POST /:id/weigh`（requireSupplier，status==='已确认'）：逐行写 actualWeight/weighed；`actualLineTotal = actualWeight>0 ? +(actualWeight×unitPrice).toFixed(2) : totalPrice`；`totalAmount=ΣactualLineTotal`；`actualPayAmount=max(0,totalAmount-discountAmount)`（券面值不重算）；`items.every(weighed)` → `sorted=true`+`sortedAt`
3. `POST /:id/deliver-photo`（requireSupplier，status==='已发货'）：写 deliveryPhotoUrl/deliveredAt；复用 `sendNotification(supplier,'order_delivered_photo',{...})` 推送（console.log 占位，与现有通知一致）

> 收货结算 `confirmReceiveHandler`（第414行）读 live `order.totalAmount`，分拣阶段已刷新 totalAmount，故积分/返点/发币自动按实称重算，无需改。

**server.js** `PUT /api/settings` 末尾追加配送字段清洗：经纬度转 Number/null、receiveMethod enum 校验、地址/照片字符串截断。

## 验收测试
1. **接口**：dev token/merchant token/supplier token 分别打 GET /:id 验权限隔离；POST /:id/weigh 逐行→全行验 sorted/totalAmount 重算；POST /:id/deliver-photo 验 deliveredAt；非法 receiveMethod 应被剔除
2. **浏览器**：供应商登录→订单页打票(80mm 版式)、一键打全票(弹一次出多页)；分拣过秤页手输重量→金额刷新+标签打印+全行后已分拣；秤配置切 webserial→弹串口选择(无设备报错手输兜底)；配送单页门头照点开放大、导航跳高德 URI、拍照送达后变已送达
3. **商家端**：店铺设置填定位/门头照/方式/时段→保存回填；供应商配送单页能看到该商家门头照+定位；订单详情看实称数量+实付金额
4. **回归**：下单→确认→发货→收货结算(积分/返点/发币)链路不受影响；30 秒轮询、资质上传/装修/改价/合作结算页不受影响

## 关键决策
- **getScaleWeight()**：localStorage adapter 分派，manual 默认返回 null 走手输，零侵入；WebSerial 骨架可运行
- **实称重算**：行 actualLineTotal=actualWeight×unitPrice（无称重沿用 totalPrice 防丢金额），订单 totalAmount=Σ，actualPayAmount=max(0,total-discount)；券面值不重算；返点/积分/发币收货时按 live totalAmount 重算
- **商家看实称**：GET /:id 返回行级 actualWeight/actualLineTotal + 订单 actualPayAmount；列表实付列已自动反映
